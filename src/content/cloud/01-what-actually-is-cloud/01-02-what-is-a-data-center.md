# 01.2 — What Is a Data Center?

We now understand what a server is. It is a machine that delivers some service to clients over the network. But there is one important detail that we have not yet discussed: a server needs to reside somewhere!

A server cannot be some abstract concept that magically floats around on the Internet. At the end of the day, it needs to be implemented on some physical hardware. This requires power, networking, cooling, storage, space, and even people. This is where a data center comes in.

A data center is a facility that hosts and maintains computing infrastructure. At a small scale, that might mean a room with a few servers. At a larger scale, it can mean a large building with thousands of servers, storage, networking, power, cooling, monitoring, and even physical security equipment. The key point is that a data center is not just a room with computers in it.

The computers are only a part of the infrastructure. Everything else is there to ensure these machines can perform their job. To better understand what a data center is, let us think about what a server actually requires.

Think of a physical server you have bought and want to use to host some application 24/7. Where would you put it? What infrastructure would you need to complement it?

Let us try to think in terms of requirements:

- Computing power.

- Electricity.

- Networking infrastructure to connect clients to the server.

- Cooling infrastructure to get rid of the heat generated by the server.

- Some physical security to ensure the server cannot be tampered with.

- Monitoring infrastructure to ensure everything works as expected.

## Why Can’t We Simply Put Our Servers in the Office?

You absolutely can. In fact, that is what some companies do. A small business may not need a dedicated data center. They can simply put their servers in a room at the back of the building.

The issue starts when the scale begins to grow. When you have to think in terms of tens or hundreds of servers, not only do you need more space, but you also need more power, better connectivity, more and better cooling, etc.

You also have to think about fault tolerance. You cannot have a single point of failure. The following illustration shows potential issues that can arise when you have many interconnected servers:

1. Your entire line of business depends on an application your company hosts.

2. The application runs on one single server.

3. That server has a power supply, a cooling system, and is connected to the Internet.

4. The server can fail, the power supply can fail, the cooling system can fail, or the Internet connection can be cut.

When operating at this scale, an organization has to plan for such possibilities and ensure there are always spare parts and redundant connections so that a single point of failure affects as little as possible.

This is why large organizations require a dedicated data center.

## Power Is a Big Concern

Electricity is something we rarely think about. We flip a switch and get power without thinking about all the infrastructure needed to make that happen.

When an organization has many servers, however, power becomes a serious concern.

Let us think in terms of infrastructure:

```text
Power Grid
    ↓
Power Infrastructure
    ↓
Data Center
    ↓
Servers + Storage + Networking

```

As you can see, a data center is not a single entity. It is part of a larger infrastructure that ultimately gets power from the local power grid.

This means that, if the power grid fails, the server will be affected. The same applies to any equipment between the grid and the server.

It is therefore common to have a data center implement some form of backup power, such as batteries and generators, so that, in case of a blackout, the power can be rerouted to the data center infrastructure.

The illustration below shows a simple representation of the principle.

The idea is that, in case of a power failure, the backup power source will keep the servers running for a limited amount of time.

This is the first time we are seeing the concept of redundancy. Redundancy is the ability to have more than one component for a given infrastructure need. We will revisit the topic later, but it is worth noting that, when designing reliable infrastructure, we try to avoid single points of failure.

## Cooling Is Not Optional

Another infrastructure need many organizations overlook is cooling. It seems like a mundane part of operations, but it is essential for any large-scale server deployment.

Modern computers are marvels of technology that can perform countless operations per second. But a large part of that performance is converted to heat.

Think of all the components that need power to operate: the CPU, memory, storage, GPUs, etc. In order to generate that power, the components need to resist electrical charges, which generates heat. This heat needs to be dissipated somehow.

If an organization puts servers in an enclosed space that lacks proper cooling, you can expect the temperature to rise quickly. This is why a data center has to have proper cooling infrastructure.

The illustration below provides a simple view of the concept.

```text
Servers
    ↓
Generate Heat
    ↓
Cooling System
    ↓
Heat Removed
    ↓
Equipment Stays Cool

```

Some data centers will implement specific cooling technologies, but the principle remains the same.

The cloud may sound abstract, but it ultimately relies on physical servers that require cooling infrastructure. This is one of the reasons why, at large scale, the cloud is not simply about software. It is about physical infrastructure that must be maintained.

## The Network Needs to Be Reliable Too

A server rarely operates by itself. Your application probably needs to communicate with a database, a cache, some storage, other servers, and your users.

This is why a data center needs to provide solid networking infrastructure.

The illustration below shows a simple view of how a data center network might be designed.

Internet  ↓  Edge Routers  ↓  Core Network  /   |   \ Server  Server   Storage  |   |   \    Internal Network

As you can see, the data center can resemble a computer itself. It consists of multiple components that need to communicate with one another reliably.

The network is often the overlooked infrastructure need in a data center. After all, even the most reliable server in the world is useless if there is no way for users to reach it.

## What Happens When There Is a Failure?

The data center concept becomes far more interesting when we start thinking about failures. Unfortunately, not only can things fail in a data center, they are inevitable.

The illustration below shows some of the most common points of failure in a data center:

Servers  /   \   Power Supply Cooling System  /   \   /   \   Switch   Disk Storage  /   \   Internet Users

A server can fail. A cooling system can malfunction. A switch can have an outage. A disk can fail. The power supply can be interrupted. The list goes on. You cannot plan for everything, but you can reduce the impact a single point of failure can have.

Redundancy is the key to building reliable systems.

Let us think about a system that has two identical servers to provide the same service:

Service Server A   \   / Server B

If Server A fails, Server B will keep the service running. The same principle can be applied to every component a data center uses.

The idea is not to build systems that do not fail, but rather systems that tolerate a point of failure without completely stopping.

That principle is essential to understand when it comes to cloud computing. Specifically, the concept of high availability and disaster recovery.

## Security Is a Physical Need Too

Even if you have a secure application with strong authentication, it does not mean you are safe if someone walks into the room where your servers are hosted and unplugs them.

That is why data centers also have to provide physical security.

Physical security can vary depending on the data center, but it should be enough to protect the physical infrastructure from unauthorized access.

The illustration below shows a simple implementation of physical security.

```text
Controlled Access
        ↓
Surveillance Cameras
        ↓
Restricted Areas
        ↓
Monitoring Infrastructure
        ↓
Physical Infrastructure

```

In essence, there should not be a way for an unauthorized person to reach the servers, switches, or storage devices. That principle should be respected at every level of physical security.

Physical security might seem like an afterthought to infrastructure design, but it is extremely important.

As a developer, you might think about application security first, but your application ultimately runs on physical servers. Security should always be a primary concern when designing any infrastructure.

## Why Do Cloud Providers Need Such Large Facilities?

Now that we understand what a data center is, we can revisit the concept of the cloud.

Specifically, why do cloud providers need such large facilities? Why can’t they simply create all the infrastructure they need in software?

The illustration below shows the relationship between a cloud provider and a data center.

```text
Physical Infrastructure
        ↓
Data Center
        ↓
Cloud Infrastructure
        ↓
Cloud Service
        ↓
My Application

```

As you can see, every cloud provider needs some form of physical infrastructure. In other words, they cannot create virtual machines out of thin air. Real physical servers need to be hosted and maintained somewhere, and that is where data centers come in.

When a cloud provider wants to offer you a virtual machine, it will use some of the infrastructure resources at its disposal. You can think of it as renting some of the provider’s physical resources.

This is one of the most important concepts to grasp when it comes to the cloud. Whenever you create some infrastructure in the cloud, there is always a physical element to it.

The illustration below shows a simple view of what happens when you create a VM in the cloud.

```text
My VM
  ↓
Virtualization
  ↓
Physical Server
  ↓
Network
  ↓
Data Center
  ↓
Power + Cooling + Security

```

The next time you spin up a virtual machine in the cloud, remember that it ultimately resides on a physical server. You might not interact with that server directly, but it is there, and it requires power, security, and maintenance.

Now that we understand the relationship between cloud infrastructure and data centers, we can revisit the original question: what exactly is a data center?

## Mental Model

Think of a data center as an engineered building that is dedicated to maintaining and operating servers.

Servers provide the computing power, and everything else serves to support them:

```text
Servers + Power + Cooling + Networking + Security + Redundancy
                              =
                         Data Center

```

The illustration above should give you a good idea of what a data center really is.

## Practice

### Question 1

A company has a building with thousands of servers. Is that building a data center?

Answer: Not necessarily. A data center is a building designed to provide the infrastructure needed to operate computers. Simply having a building with many servers is not enough. The building would have to have redundancy, networking infrastructure, cooling, power, and security in order to qualify as a data center.

### Question 2

A server is operating normally, but the network equipment that connects it to the Internet has failed. Is it possible for users to access the server?

Answer: No. Even though the server may be operating normally, users would not be able to access it if the network equipment fails.

### Question 3

A data center loses external power for a few seconds. Why might the servers continue to operate?

Answer: Many data centers have backup power supplies and generators in order to ensure uninterrupted power delivery. This means that, even if the external power is cut, the servers can continue operating while the generator starts up.

### Question 4

Why might a cloud provider choose to operate infrastructure in multiple geographic locations?

Answer: Latency and reliability are two important factors when choosing where to host cloud infrastructure. Having servers in multiple geographic locations can help reduce latency for users in distant locations. It can also increase reliability in the event of a disaster affecting one location.

### Question 5

A cloud dashboard provisions a VM in 30 seconds. Was a physical server created in 30 seconds?

Answer: No. The physical servers already exist. The cloud infrastructure simply provisions a VM using some of the available resources.

### Question 6

Why is the phrase “the cloud is just someone else’s computer” useful, but ultimately misleading?

Answer: The phrase is useful because it helps explain that the cloud is ultimately built upon infrastructure that other companies operate. It is misleading, however, because it ignores the complexity involved in cloud infrastructure.

## The Takeaway

A data center is much more than simply a building where servers are hosted.

In reality, it is an engineered building where servers can operate reliably. It provides the infrastructure servers need to operate, such as power, networking, cooling, security, and redundancy.

Servers need all of the above to tolerate hardware failures, provide uninterrupted service, and prevent downtime. Redundancy ensures that there is always a backup system in the event of a disaster.

Cloud providers operate large-scale data centers and offer their services to individuals and companies through the cloud. As such, every time you create a server in the cloud, you are actually interacting with a physical server that resides in a data center.

The illustration below is a good reminder of what happens every time you create a cloud service:

```text
Cloud Service
      ↓
Virtual Infrastructure
      ↓
Physical Server
      ↓
Data Center
      ↓
Power + Cooling + Networking + Security

```

Everything you do in the cloud is abstracted away behind layers of infrastructure. Now that you understand the physical aspects of cloud computing, it is time to move on to the next concept: cloud computing itself.
